## 1. WebSocket `/ws` — 서버 → 브라우저 메시지

기존 `tick`(1초) · `snapshot`(3초) · `error` 는 그대로. 새 메시지 셋:

### 1-1. `watchlist` (5초마다, 바이낸스 공개 `ticker/24hr` 한 번 호출)

```json
{"type":"watchlist","ts":"...","focus":"SOXLUSDT",
 "items":[{"symbol":"SOXLUSDT","price":131.80,"change_pct":0.47,
           "quote_volume":1.2e7,"lev_tag":"3x","collected":true}],
 "basket_exposure_x":1.9}
```
- `items` 는 `th.universe.STOCK_PERPS` 순서(36개). 바이낸스에 없는 심볼은 빠진다.
- `lev_tag`: `th.universe.LEVERAGE_TAG` (SOXL 3x, SOXS -3x, TQQQ 3x, SQQQ -3x, TZA -3x, UVXY 1.5x), 없으면 `null`.
- `collected`: `TH_SYMBOLS` 에 있어 DB 에 1분봉이 있는 종목.
- `basket_exposure_x` = Σ|포지션 노셔널| ÷ 지갑. 계정 조회 실패면 `null`.

### 1-2. `market` (20초마다, `premium_index` + DB)

```json
{"type":"market","ts":"...","symbol":"SOXLUSDT",
 "funding_rate":0.000172,"next_funding_at":"2026-09-10T16:00:00+00:00",
 "mark_price":131.81,"underlying_price":43.92,"basis_pct":0.04,
 "underlying_ticker":"SOXL"}
```
- 브라우저가 `next_funding_at` 까지 카운트다운을 매초 센다.
- 본주 값이 없으면 `underlying_price`/`basis_pct` 는 `null`.

### 1-3. `snapshot` 에 추가되는 `discipline` (3초, 규율 지표)

```json
"discipline":{
  "total_exposure_x":2.1,"total_limit_x":3.0,
  "max_symbol":"SOXLUSDT","max_symbol_exposure_x":0.9,"symbol_limit_x":1.0,
  "daily_pnl_pct":-1.8,"drawdown_limit_pct":15.0,
  "remaining_r":2.6,"r_limit":3.0,
  "event_blocked":true,"event_name":"FOMC 금리 결정","event_in_sec":2480,
  "closes_in_sec":15160,"ok":true}
```
- `total_exposure_x` = Σ|노셔널| ÷ 지갑 (전 종목, `positions()` 전체 조회).
- `max_symbol_exposure_x` = 가장 큰 단일 종목 노셔널 ÷ 지갑.
- `daily_pnl_pct` = (오늘 실현 + 미실현) ÷ 지갑 × 100. 미실현은 전 종목 합.
- `remaining_r` = `r_limit − max(0, −daily_r)`; `daily_locked` 면 0.
- `event_blocked` = 세션 게이트가 이벤트 사유로 차단 중. `closes_in_sec` = 본주 휴장(POST 끝)까지.
- 계정 조회 실패면 `ok:false` 이고 숫자는 `null` — 브라우저는 마지막 값을 유지하고 흐리게.
- 한도 상수는 `th.account.risk` 에 `EXPOSURE_LIMIT_X=3.0`, `SYMBOL_LIMIT_X=1.0`, `DRAWDOWN_LIMIT_PCT=15.0`, 기존 `DAILY_LOSS_LIMIT_R=3.0`.

### 1-4. `brackets` (3초, 페이퍼 브래킷 패널)

```json
{"type":"brackets","ts":"...","mode":"paper","available":true,
 "open":[{"id":"a1b2c3d4","symbol":"SOXLUSDT","direction":"LONG",
          "entry":132.50,"stop":131.25,"tp1":134.09,"tp2":135.68,
          "qty":41.67,"position_qty":20.8,"has_stop":true,
          "status_ko":"손절 대기 · 잔여 50%","realized_r":0.0,
          "risk_per_unit":1.25,"close_requested":false}],
 "today_realized_r":1.2,"today_count":3,"expectancy_r":0.18}
```
- 열린 브래킷의 **평가 R** 은 브라우저가 매초 계산: `(price − entry) × 방향 ÷ risk_per_unit`
  (진입 전이면 `—`).
- `status_ko` 는 서버가 만든다: `진입 대기 · 지정가 · N:NN 후 만료` / `손절 대기 · 잔여 50%` /
  `TP1 체결 → 손절 본절 이동` / `청산 요청됨`.
- 차트에는 **포커스 종목** 브래킷의 EN/SL/TP1/TP2 가로선을 그린다.

### 1-5. `focus` (포커스 종목이 바뀌면 즉시)

```json
{"type":"focus","symbol":"NVDAUSDT","collected":false}
```

## 3. 브라우저에서 청산 버튼 → 페이퍼 러너

웹 서버 프로세스에는 `BracketManager` 가 없다. 그래서 **요청만 DB 에 남긴다**:

- 마이그레이션 `005_close_request.sql`: `brackets.close_requested_at timestamptz NULL`.
- `store.request_close(bracket_id, mode)` — 열린 페이퍼 브래킷에만 표시. `store.pending_close_requests(mode)`.
- `th paper run` 루프가 매 반복마다 `pending_close_requests("paper")` 를 확인하고 `mgr.close_now(id)` 실행 후 표시를 지운다.
- 러너가 안 떠 있으면 버튼은 눌리지만 `status_ko` 가 `청산 요청됨 · 러너 대기` 로 남는다 — 브라우저는 그걸 그대로 보여준다.
- 실거래에서는 이 경로가 **아예 존재하지 않는다** (403). `th.account` 에는 여전히 주문 코드가 없다.

## 4. 차트 — 팬/줌

- **드래그**: 좌우 팬. 드래그 시작 시 "최신 따라가기" 해제. 위아래 드래그는 무시(가격축 자동).
- **휠**: 커서 위치 기준 확대/축소. 보이는 봉 수 20~600.
- **더블클릭 또는 "최신" 버튼**: 마지막 봉으로 복귀 + 따라가기 재개.
- 따라가기 중에는 살아있는 봉이 항상 오른쪽 끝 + 여백 8봉.
- 팬 중에도 **살아있는 봉과 가격선은 매초 갱신**된다 (보이는 범위 안이면).
- 가격축(오른쪽 62px)은 보이는 봉 + 가로선(SL/EN/TP/현재가) 기준으로 자동.
- 봉은 `S.bars`(닫힌) + `S.live` 에서 **보이는 구간만** 그린다. 데이터가 왼쪽 끝에 닿으면 `/api/candles?limit=` 를 늘려 더 받는다 (최대 1200).
- 크로스헤어: 마우스 위치의 봉 OHLC 를 상단 툴바에 표시 (마우스가 나가면 살아있는 봉 OHLC).

## 5. 바꾸지 않는 규칙 (tests/test_web.py 가 지킨다)

- 외부 리소스 0 (`<link>`·`<script src>` 없음), 브라우저 저장소 사용 안 함.
- 지표(EMA·VWAP) 계산은 서버. 브라우저는 살아있는 봉 한 칸만 잠정 연장.
- 방향을 제시하는 말("매수 추천" 등) 없음. `no_trade` 는 사유만.
- 계정 조회 실패는 "포지션 없음"으로 그리지 않는다 — 마지막 값 + "마지막으로 확인된 값".
- 한 화면, 스크롤 없음 (`overflow:hidden`, 100dvh grid).

## 7. 주문 패널 (`#order`)

탭 **페이퍼** | **실매매**.

- **페이퍼 탭** — 폼: 종목(포커스 종목, 읽기전용 표시) · 방향 LONG/SHORT 토글 · 진입(비우면 시장가, 값 넣으면 지정가) ·
  손절(필수) · TP1 · TP2 · 위험 % (기본 `settings.risk_pct`) · 만료(초, 기본 300).
  손절/TP 값을 바꿀 때마다 `POST /api/orders/preview` 로 **수량·노셔널·1R(USDT)·손절폭%·비용/R·가드 경고**를 받아 폼 아래에 보여준다.
  `주문 넣기` → `POST /api/orders` → 성공 시 브래킷 패널에 즉시 나타난다(서버가 `brackets` 를 바로 브로드캐스트).
  가드에 걸리면 사유를 빨갛게 폼 아래에 나열하고 아무것도 열지 않는다.
- **실매매 탭** — **잠김 화면**. 폼은 비활성이고 docs/07 게이트 조건 목록(`GET /api/orders/gate`)을 체크리스트로 보여준다.
  `TH_EXECUTION_MODE=live` 여도 이 화면은 잠겨 있다 — 실거래 주문 경로는 아직 존재하지 않는다(`LiveClient` 는 `NotImplementedError`).
  서버는 `mode:"live"` 주문을 무조건 **403** 으로 거절한다.

### 서버 — 페이퍼 엔진이 `th serve` 안에서 돈다

`execution_mode == "paper"` 이면 `th serve` 가 시작할 때 **PaperRunner**(BracketManager + PaperClient + 호가 피드 + 만료 + 청산 요청 처리)를 백그라운드 태스크로 띄운다.
`th paper run` 의 루프와 같은 코드를 `src/th/execution/runner.py` 로 옮겨 둘 다 쓴다.
같은 브래킷을 두 프로세스가 관리하지 않도록 `th paper run` 은 `th serve` 가 떠 있으면(DB `runner_lease` 로 판단) 경고하고 종료한다.
주문 생성은 CLI 와 **완전히 같은 경로**: `size_from_risk` → `round_qty/round_price` → `GuardInput`(daily_locked·open_bracket_count·session_blocked 포함) → `mgr.open()`.
`th.account` 에는 여전히 주문 코드가 없다. 주문 코드는 `th.execution` 에만 있다.

## 8. 실매매 포지션 (`positions` 메시지, 3초)

```json
{"type":"positions","ts":"...","ok":true,"wallet_usdt":2890.5,
 "items":[{"symbol":"SOXLUSDT","side":"LONG","qty":12.61,"entry_price":125.62,"mark_price":117.21,
           "notional_usdt":1478.0,"unrealized_pnl":-106.0,"unrealized_pct":-6.7,
           "liquidation_price":109.88,"liq_distance_pct":6.22,"underlying_move_to_liq_pct":-2.1,

```
- 전 종목 (`client.positions()` 전체 + `open_orders()` 전체에서 STOP 주문을 종목별로 매핑).
- 계정 조회 실패면 `ok:false`, `items` 는 마지막 값 유지(브라우저가 흐리게 + "마지막으로 확인된 값").
- 브라우저는 `mark_price` 대신 포커스 종목이면 `S.price`, 아니면 워치리스트 가격으로 **평가손익을 매초** 다시 계산한다.
- 열 순서: 종목 · 방향 · 수량 · 진입 · 현재가 · 평가손익(USDT·%) · 청산가 · 청산까지% · 손절주문 · 실효배수.
  손절 없음은 빨갛게. 이 표가 예전 `청산까지`·`포지션` 패널을 대체한다.

## 9. 유니버스 확장 (`th.universe`)

- 후보 목록을 넓힌다 — 반도체: `SOXL SOXS SMH NVDA AMD INTC SMCI AMAT AVGO TSM ASML MU QCOM TXN ARM LRCX KLAC MRVL ADI ON MCHP MPWR SNDK WDC STX MRVL`
  (+ 기존 지수ETF·대형기술주·기타). `GROUP_OF[symbol]` 로 그룹 태그.
- **실제 목록은 바이낸스가 정한다**: 서버가 시작할 때 `exchange_info()` 를 한 번 받아

  (b) 로 새로 발견된 심볼은 그룹 `기타` 로 넣고 로그에 남긴다 — 우리가 모르는 상장 종목도 자동으로 잡힌다.

  바이낸스 공개 5분봉(닫힌 것 1000개)을 받아 `th.backtest.ma5m.latest_state()` 로 국면·신호를 계산한다.
  **백테스트와 같은 함수다** (`tests/test_ma5m.py` 가 스크립트 Y1~Y4 와 매매 단위로 동일함을 못 박는다).
- 그 종목에 엔진이 연 브래킷(`setup_id = "video200_20"`)이 있으면 ⑥ 청산 규칙(종가가 EMA20 을 반대로) 또는 보유 시간 만료(288봉)에 `mgr.close_now()`.
  손주문 브래킷은 건드리지 않고, 그 종목에는 새로 열지도 않는다.
- 브래킷이 없고 신호가 있으면 `PaperRunner.open_from_request(OpenRequest(...))` — **웹 주문 패널·CLI 와 완전히 같은 경로**
  (수량 역산 → 반올림 → 안전장치 → 매니저). 가드가 막으면 건너뛰고 사유를 남긴다.
  손절은 **현재가** 기준 `min(TH_SIGNAL_HARD_STOP_PCT, 2.95)%` (신호 봉 종가 기준이면 시가가 뛰었을 때 가드 상한 3% 를 넘긴다).
  `risk_pct = 손절폭 × TH_SIGNAL_NOTIONAL_X` → 노셔널 = 시드 × 1.0 (= "시드 10% 를 10배").
- 판단은 `signal_log` 테이블(마이그레이션 007)에 남긴다. `open | skip | exit | error`. `none`(신호 없음)은 DB 에 안 남기고 메모리 최근 목록에만 둔다.
- 설정: `TH_SIGNAL_ENABLED`(기본 true — 꺼도 관찰은 계속), `TH_SIGNAL_MODE`(both|pullback|squeeze), `TH_SIGNAL_NOTIONAL_X`, `TH_SIGNAL_HARD_STOP_PCT`,
  `TH_MAX_OPEN_BRACKETS`(가드 동시 브래킷 수, 기본 1 — 4종목 다 돌리려면 4).
- 주문을 내려면 그 종목이 `TH_SYMBOLS` 에 있어 `th stream` 이 호가를 적재하고 있어야 한다. 없으면 관찰만 하고 `skip: 시세 없음`.
- 세션 게이트(docs/05)는 **주식 perp 에만** 적용된다. BTC·ETH 는 본주 정지 개념이 없으므로 통과 (`runner.session_gate`).

| 경로 | 뜻 |
|---|---|
| `GET /api/engine` | `{available, enabled, alive, symbols, params, label_ko, notional_x, next_at, ticks, states:[{symbol, ok, bar_at, close, ema20, ema200, gap_pct, trend, chop, squeezed, signal, kind_ko, phase_ko, open, last_action, last_reason, error_ko}], recent:[...], collected}` |

## 11. 백테스트 페이지 (`/backtests`, `src/th/api/web/backtests.html`)

왼쪽: 실시간 엔진(종목 카드 = 국면·종가·EMA20/200·간격·신호·열린 브래킷, 최근 판단, 켜기/끄기, 다음 판단 카운트다운) + 새 백테스트 폼.
오른쪽: 실행 목록(4초 폴링) + 상세(판정 5항목, 전체/뒤집기/IS/OOS 카드, 누적 R·시드 배수 곡선, 월별 R, 매매 목록).

| 경로 | 뜻 |
|---|---|
| `GET /api/backtests/data` | 종목별 데이터 소재 `{items:[{symbol, csv:{path,mb}|null, db:{from,to,bars_1m}|null}], binance_max_days}` |
| `POST /api/backtests {symbol, source:csv|db|binance, since:"YYYY-MM", params:{mode, session, hard_stop_pct, squeeze_pct, chop_max, body_mult, max_hold_bars, cost_pct, funding_8h_pct, seed_pct, leverage}}` | 접수 → `{ok,id}`. 백그라운드로 돌고 `backtest_runs` 에 남는다 |
| `GET /api/backtests?limit` | 목록 (`summary` 에 핵심 지표) |
| `GET /api/backtests/{id}` | 전체 결과 (`result.trades` 는 최근 3000건까지) |
| `DELETE /api/backtests/{id}` | 삭제 |

판정(`verdict`) 5항목: 표본 ≥100 · 기대값 ≥+0.05R · t ≥2 · 뒤집기가 더 나쁨 · OOS 양수. 5/5 통과, 3~4 약함, 그 이하 탈락 (docs/14 규칙).
데이터: `csv` 는 `dataset/vision/{SYMBOL}_1m.csv`(가장 김), `db` 는 수집 종목 1분봉, `binance` 는 공개 5분봉을 뒤로 넘기며 최근 400일.

## 12. 매매기록 페이지 (`/history`, `src/th/api/web/history.html`)

`GET /api/history?limit&setup=all|auto|manual` → `th.api.history.build_history()`:
`{summary, auto, manual, by_symbol, by_direction, by_reason, curve:[{t,cum_r,cum_pnl}], daily:[{day,n,sum_r,sum_pnl,wins}], items:[...], open:[...], min_sample:30}`.
- **체결된 브래킷만** 매매로 센다. 유효시간 만료로 체결 없이 닫힌 것은 `unfilled` 로 따로 센다.
- 승률·기대값·PF·MDD(R)·최대 연패 정의는 백테스트(`ma5m.summarize`)와 같다 — 두 화면의 숫자를 나란히 놓고 "백테스트는 됐는데 페이퍼는 안 된다"를 판단할 수 있어야 한다.
- 30건 미만이면 화면 상단에 경고. 탭(전체/자동/손주문)·종목 필터·CSV 내려받기. 열린 브래킷은 목록 맨 위에 흐리게.
- `brackets` 메시지의 항목에 `setup_id` 가 추가됐다(대시보드 브래킷 행에 `자동` 칩).
