# AI 분석 파이프라인

작성일: 2026-08-29

요청하신 구조 그대로다: **두 모델이 각자 시나리오를 만들고 → 대조하고 → 이벤트·뉴스를 얹어 → LLM이 한 문단으로 정리.**

```
                    ┌──────────────────────────────┐
   5분봉 마감 ──────▶│ A. 유사 패턴 검색 (k-NN)      │──▶ 시나리오 A
                    └──────────────────────────────┘
                    ┌──────────────────────────────┐
              ──────▶│ B. 확률 예측 (LightGBM)       │──▶ 시나리오 B
                    └──────────────────────────────┘
                                   │
                    ┌──────────────▼───────────────┐
                    │ C. 시나리오 대조              │──▶ 일치도 / 판단보류 여부
                    └──────────────┬───────────────┘
                    ┌──────────────▼───────────────┐
   캘린더·뉴스 ─────▶│ D. 이벤트 해석 레이어         │──▶ 무효화 / 경고
                    └──────────────┬───────────────┘
                    ┌──────────────▼───────────────┐
                    │ E. LLM 종합 브리핑            │──▶ 한 문단 + 핵심 리스크
                    └──────────────────────────────┘
```

**먼저 솔직하게:** 1분·5분 단위 가격 예측에서 머신러닝이 뽑아내는 우위는 대체로 얇다. 이 파이프라인의 실제 가치는 "맞추는 것"보다 **두 모델이 엇갈릴 때 진입을 막는 것**과 **왜 그렇게 봤는지 근거를 남기는 것**에 있다. 그래서 7절 검증 게이트를 통과 못 하면 해당 모듈은 UI에서 내린다.

## A. 유사 패턴 검색 (k-NN)

> "지금 이 차트 모양이 과거에 나왔을 때, 그 다음엔 어떻게 됐나"

### A.1 벡터 구성

최근 **60개 5분봉(=5시간)** 을 하나의 벡터로:

```python
# 봉별 시계열 피처 (60 × 5 = 300차원)
per_bar = [
    log_return,                      # 로그 수익률
    (close - vwap) / atr,            # VWAP 거리 (ATR 정규화)
    volume / volume_ma20,            # 상대 거래량
    (high - low) / atr,              # 봉 크기
    (close - low) / (high - low),    # 봉 내 종가 위치
]
# 윈도우 전체를 z-score 정규화 → 가격 수준이 아니라 '모양'만 남김
```

가격 수준을 지우는 게 핵심이다. SOXL이 30달러일 때와 60달러일 때의 같은 패턴이 같은 이웃으로 잡혀야 한다.

### A.2 검색

| 항목 | 값 |
|---|---|
| 인덱스 | FAISS `IndexHNSWFlat`, 코사인 유사도 |
| 코퍼스 | SOXLUSDT perp 전 구간 + **본주 SOXL 1분봉 장기** (perp 히스토리가 짧아 본주로 보강) |
| 후보 제한 | **같은 세션 레짐만** (🟢은 🟢끼리) |
| 중복 제거 | 서로 30봉 이내로 겹치는 윈도우는 하나만 채택 ← 안 하면 같은 사건이 50번 뽑혀 표본이 뻥튀기됨 |
| K | 50 (유사도 임계 0.85 미만은 버림) |

> ⚠️ **선행 조건:** 본주 장기 1분봉이 아직 없다. yfinance 는 최근 30일만 제공하므로
> Phase 4 착수 전에 Alpaca 어댑터를 추가해야 한다 (`04-개발-로드맵` Phase 4 첫 항목).

### A.3 출력 — 시나리오 A

찾은 K개 사례 각각에 대해 **지금과 동일한 TP/SL 규칙**(`02` 문서 5절)을 적용해 결과를 재현한다.

```jsonc
"scenario_a": {
  "method": "similar_pattern",
  "matches": 48,                    // 유사도 임계 통과 수
  "mean_similarity": 0.91,
  "direction_bias": "up",
  "up_ratio": 0.62,                 // 이후 24봉 내 상승 마감 비율
  "tp1_first_ratio": 0.58,          // TP1이 SL보다 먼저 닿은 비율 ← 시나리오 A의 승률
  "return_quartiles_pct": [-0.9, 0.4, 1.3],   // 이후 24봉 수익률 25/50/75%
  "median_bars_to_tp1": 5,
  "worst_case_mae_pct": -1.8,       // 최악 사례의 최대 역행폭
  "top_examples": [
    { "date": "2026-03-12T14:05Z", "session": "RTH", "outcome": "TP1", "return_pct": 1.4 }
  ]
}
```

`worst_case_mae_pct`는 반드시 표시한다. 10배에서는 "평균적으로 오른다"보다 **"최악의 경우 얼마나 역행했나"** 가 훨씬 중요한 정보다.

## B. 확률 예측 모델 (LightGBM)

> "이 조건에서 손절 전에 목표가 닿을 확률"

### B.1 라벨 — 삼중 배리어

각 시점에서 위·아래·시간 세 개의 벽을 세우고 무엇에 먼저 닿는지 기록한다.

```
상단 배리어 = 진입 + 2.0R   (TP1)
하단 배리어 = 진입 − 1.0R   (SL)
시간 배리어 = 48봉 (4시간)

label = 1  if 상단 먼저
        0  if 하단 먼저 또는 시간 만료 시 손실
```

### B.2 피처 (약 40개)

| 그룹 | 예시 |
|---|---|
| 추세 | EMA9/21 스프레드, 15분봉 방향, VWAP 거리(ATR 정규화) |
| 모멘텀 | RSI(9,1m), RSI(14,5m), RSI 변화율, 다이버전스 플래그 |
| 변동성 | ATR%, ATR 퍼센타일, 볼린저 폭, 최근 20봉 실현변동성 |
| 거래량 | 상대 거래량, CVD 기울기, 거래량 급증 플래그 |
| **Perp 고유** | ΔOI(5m/15m), 펀딩률, 다음 정산까지 시간, basis, 호가 스프레드 |
| **세션** | 레짐 원핫(4), 개장 후 경과분, 마감까지 남은 분 |
| **이벤트** | 다음 고중요도 이벤트까지 분, 오늘 FOMC/실적 여부, OPEX 여부 |
| 시장 | VIX, SOXX 당일 수익률, SPY 당일 수익률 |

세션·이벤트 피처가 들어가는 게 이 모델의 차별점이다. "같은 RSI 45라도 개장 20분 뒤와 런치 구간은 완전히 다른 상황"을 모델이 배우게 된다.

### B.3 학습 — 시계열 누수 방지

```
Purged Walk-Forward CV + Embargo
  · 학습/검증 구간 사이에 48봉 공백(embargo)을 둔다
  · 라벨 기간이 겹치는 샘플은 학습에서 제거(purge)
  · 무작위 K-fold 절대 금지 ← 미래 정보가 새어 AUC가 가짜로 올라감
```

- 클래스 불균형: `scale_pos_weight` 조정
- **확률 보정**: 홀드아웃에 isotonic regression 적용. 보정 안 하면 "68%"가 실제 68%가 아니다.
- 재학습: 주 1회 (일요일, 🔴 구간)

### B.4 출력 — 시나리오 B

```jsonc
"scenario_b": {
  "method": "gbm_probability",
  "p_tp1_first": 0.58,
  "calibrated": true,
  "model_version": "lgbm-2026w34",
  "auc_oos": 0.61,                  // 최근 검증 성능 — 사용자에게도 노출
  "brier": 0.228,
  "top_features": [                 // SHAP 상위 5개 = 근거
    { "name": "VWAP 거리", "value": "-0.12 ATR", "contribution": +0.07 },
    { "name": "ΔOI(15m)", "value": "+2.1%",     "contribution": +0.05 },
    { "name": "마감까지 남은 시간", "value": "134분", "contribution": +0.02 },
    { "name": "펀딩률", "value": "+0.041%",     "contribution": -0.03 },
    { "name": "ATR 퍼센타일", "value": "78%",    "contribution": -0.04 }
  ]
}
```

## C. 시나리오 대조

두 모델은 접근이 전혀 다르다 — A는 "과거 사례의 실제 결과", B는 "조건에서 학습한 확률". **엇갈릴 때가 정보다.**

| 조건 | 판정 | 조치 |
|---|---|---|
| 방향 일치 & \|p_A − p_B\| ≤ 0.10 | ✅ **강한 합의** | 신뢰도 `+10` |
| 방향 일치 & 0.10 < 차이 ≤ 0.20 | 🟢 합의 | 변동 없음 |
| 방향 일치 & 차이 > 0.20 | 🟡 **약한 합의** | 신뢰도 `−10`, 브리핑에 불일치 명시 |
| 방향 불일치 | 🔴 **판단 보류** | **신호 발행 중단.** "두 모델이 반대 방향" 표시 |
| A 표본 < 20 또는 B 미학습 | ⚪ 데이터 부족 | AI 블록 숨김, 규칙 엔진 결과만 표시 |

```jsonc
"agreement": {
  "status": "strong",              // strong | ok | weak | conflict | insufficient
  "p_a": 0.58, "p_b": 0.58, "gap": 0.00,
  "direction_match": true,
  "confidence_adjustment": +10
}
```

한쪽만 믿는 것보다, **둘이 갈릴 때 손을 놓는 것**이 10배 레버리지에서 훨씬 값어치가 크다.

## D. 이벤트 · 뉴스 해석 레이어

### D.1 수집

| 소스 | 내용 | 주기 |
|---|---|---|
| 경제지표 캘린더 (Finnhub) | CPI·NFP·FOMC 등 일정과 중요도 | 하루 1회 + 장 전 재확인 |
| 실적 캘린더 | SOXX 상위 10종목 발표일·시간 | 하루 1회 |
| 뉴스 (Finnhub news + RSS) | 반도체·관세·수출규제·개별종목 | 5분 |

### D.2 LLM 구조화

수집한 뉴스 헤드라인을 LLM이 **판단이 아니라 분류**만 한다.

```jsonc
// 입력: 헤드라인 + 요약 (원문 링크 보존)
// 출력:
{
  "relevant": true,
  "affected": ["NVDA", "SOXX"],
  "polarity": "negative",          // positive | negative | neutral
  "magnitude": "high",             // low | medium | high
  "expected_duration": "days",     // minutes | hours | days
  "source_url": "https://..."
}
```

`magnitude: high`가 30분 이내에 들어오면 → **게이트에 피드백해서 신규 신호를 차단**하고 배너에 띄운다. 뉴스가 방향을 정해주지는 않는다. 뉴스는 "지금 기술적 분석이 통하지 않는다"는 신호로만 쓴다.

### D.3 캘린더 연동

`05-세션-이벤트-타임맵`의 게이트가 여기서 받은 동적 이벤트를 흡수한다. 두 곳에 로직을 두지 않는다.

## E. LLM 종합 브리핑

### E.1 입력 — 오직 구조화된 숫자만

LLM에게 **원시 차트나 캔들 데이터를 주지 않는다.** A/B/C/D의 결과 JSON과 규칙 엔진의 신호 카드만 준다. 계산은 이미 끝났고, LLM은 설명자 역할만 한다.

### E.2 제약 (시스템 프롬프트에 명시)

```
1. 입력 JSON에 없는 숫자를 절대 만들지 마라.
2. 방향을 단정하지 마라. "오를 것"이 아니라 "두 모델 모두 상승 쪽"으로 쓴다.
3. 두 시나리오가 엇갈리면 그 사실을 첫 문장에 쓴다.
4. 한국어, 3~4문장, 200자 이내.
5. 매수/매도 권유 표현을 쓰지 마라.
6. 리스크를 반드시 한 줄 포함하라.
```

### E.3 출력 스키마

```jsonc
"briefing": {
  "summary_ko": "본장 중반, 가격은 VWAP 위에서 눌림을 마치고 종가가 밴드 안으로 돌아왔습니다. 유사 사례 48건 중 58%가 손절 전 1차 목표에 닿았고 확률 모델도 58%로 같은 방향이라 두 관점이 일치합니다. 다만 미결제약정이 늘고 있는 만큼 반대 방향 청산 사냥에 노출될 수 있습니다.",
  "key_risk_ko": "2시간 뒤 FOMC 성명 — 그 전에 정리하지 않으면 손절이 건너뛰어질 수 있습니다.",
  "agreement_note_ko": "두 모델 방향 일치 (58% / 58%)",
  "numbers_verified": true
}
```

### E.4 환각 차단 — 이게 없으면 이 모듈은 위험하다

생성된 텍스트에서 **모든 숫자를 정규식으로 추출**해서, 입력 JSON에 존재하는 값인지 대조한다.

```python
nums = re.findall(r"-?\d+\.?\d*", text)
if any(n not in allowed_values for n in nums):
    log_hallucination(text)
    return template_fallback(payload)   # 규칙 기반 문장으로 대체
```

검증 실패율을 지표로 추적하고, 5%를 넘으면 프롬프트를 고친다.

### E.5 호출 정책

| 항목 | 값 |
|---|---|
| 시점 | 5분봉 마감마다 1회 + 사용자가 새로고침 누를 때 |
| 대상 | 🟢🟡 레짐에서만 (🔴은 호출 안 함) |
| 하루 호출량 | 약 130회 |
| 지연 처리 | 브리핑은 **비동기**. 신호 카드와 리스크 게이지는 LLM을 기다리지 않고 먼저 뜬다 |
| 실패 시 | 템플릿 문장으로 폴백. 브리핑 없다고 신호를 막지는 않는다 |

## 7. 검증 게이트 — 통과 못 하면 UI에서 내린다

| 모듈 | 합격선 | 측정 |
|---|---|---|
| A. 유사 패턴 | 상위 K 사례의 이후 수익률 분포가 무조건부 분포와 유의하게 다름 (KS test p < 0.05) · TP1 도달률이 베이스라인 대비 +5%p 이상 | 아웃오브샘플 |
| B. 확률 모델 | **AUC ≥ 0.58**, Brier ≤ 0.24, 보정 곡선 기울기 0.8~1.2 | Purged walk-forward |
| C. 대조 | "판단 보류" 처리된 케이스의 실제 승률이 발행 케이스보다 유의하게 낮음 (= 거르는 게 맞았음) | 아웃오브샘플 |
| E. 브리핑 | 숫자 검증 통과율 ≥ 95% | 로그 집계 |

### 전체 효과 측정

```
베이스라인:  규칙 엔진만
비교군:      규칙 엔진 + AI 게이팅(C 판단보류 적용)

측정: 기대값(R), 최대 낙폭, 거래 횟수
→ 기대값이 유의하게 개선되지 않으면 AI는 '참고 정보'로만 두고
   신호 발행 여부에는 관여시키지 않는다.
```

## 8. 인프라

| 항목 | 선택 | 지연 |
|---|---|---|
| k-NN 인덱스 | FAISS, 메모리 상주 (~수십만 벡터 × 300차원 ≈ 수백 MB) | ~50ms |
| GBM 추론 | LightGBM native, 프로세스 내 | ~5ms |
| LLM | Claude API (Sonnet 급) | 2~5초, 비동기 |
| 재학습 | 주 1회 배치, 모델 파일 버전 관리 (MLflow 또는 단순 S3 + 메타 테이블) | |

모델 버전은 신호 레코드에 같이 저장한다. 나중에 "그때 왜 그렇게 나왔지"를 재현할 수 있어야 한다.
