# 17 — 뉴스·이벤트 매매 엔진 (v3.0 설계)

> 작성: 2026-09-22. 사용자 요청: **텔레그램·뉴스를 수집해서, 그날 방향이 확실해 보이는 미국 주식 토큰에
> 프리장이든 애프터장이든 뉴스가 뜨는 대로 전략을 세우고 매매한다.** 시드의 10분의 1 × 10배, 분할 진입 가능,
> 보유 몇 시간~1주일, 목표 마진 대비 +20~100%. 바이낸스 선물에 상장된 **모든** 미국 주식 토큰이 대상.
>
> 이 문서는 docs/06 D절의 결정("뉴스는 방향을 정하지 않는다, 차단 신호로만 쓴다")을 **뒤집는다.** §1 에 근거를 적는다.

---

## 0. 한 줄 요약

```
수집(텔레그램 채널 + RSS + SEC 공시)  →  전처리(중복 제거 · 종목 매핑)
   →  판단(Claude API: 종목·방향·확신도·분할 계획·손절·목표)
   →  작전(Campaign) 생성  →  안전장치(기존 가드 + 노출 한도)
   →  페이퍼 자동 실행  /  텔레그램 승인 후 실행  →  매매기록에 합산
```

돈은 v3.0 에서도 나가지 않는다. 실거래 경로(`live.py`)는 docs/07 조건이 채워지기 전까지 잠긴 채다.
이 엔진은 **실거래로 가는 승인 흐름까지 페이퍼로 먼저 연습**한다.

## 1. 결정 — 그리고 왜 docs/06 을 뒤집는가

| 결정 | 내용 | 근거 |
|---|---|---|
| D1 | 뉴스가 **방향을 낸다** | docs/08·14 에서 기술적 셋업은 우위가 없었다. 남은 가설은 "정보(뉴스)가 가격에 반영되기 전에 잡는다" 이고, 이건 백테스트로 못 잰다 — **페이퍼로 재야 한다**. 그래서 만든다 |
| D2 | 첫 버전은 **페이퍼**, 승인 흐름은 지금 만든다 | 사용자 선택(2026-09-22). 실거래 전환이 "설정 한 줄" 이 되도록 같은 경로로 만든다 |
| D3 | 텔레그램은 **사용자 계정 세션**으로 구독 채널을 읽는다 | 사용자 선택. 봇은 채널을 못 읽는다. 알림·승인 버튼은 별도 **봇**이 한다 |
| D4 | 판단은 **Claude API** 가 한다 (구조화 출력) | 사용자 선택. 규칙 기반은 뉴스 해석 품질이 낮다 |
| D5 | 손절은 **건별로 판단 계층이 정하고 가드가 1~5% 로 제한** | 사용자 선택. 10배 격리 청산선 −9.5%, 기존 청산 여유 1% 규칙 유지 → 5% 가 물리적 상한 |
| D6 | 크기: **마진 = 시드 10% (분할 합계)**, 10배 → 노셔널 = 시드 1.0배 | 사용자 지정. docs/14 "한 종목 ≤ 1배" 와 일치 |
| D7 | 판단·작전·체결 **전부 DB 에 남긴다** | 우위가 있는지는 30건·60거래일 뒤에 매매기록 페이지에서 판정한다 (docs/15 §12 와 같은 잣대) |
| D8 | **방향 제시 금지 규칙(docs/08)의 예외** | `/api/engine` 과 같은 논리 — 이건 "지금 사라" 는 조언이 아니라 **자동 엔진의 판단 기록**이다. 화면 라벨은 "엔진 판단" 으로 고정 |

docs/06 D.2 의 "뉴스 → 게이트 차단" 기능은 **그대로 살아 있다** (`magnitude=high` 면 기술 엔진 신호 차단). 뉴스 엔진은 그 위에 얹는 별도 경로다.

## 2. 구성 — 어디에 무엇이 들어가나

```
src/th/news/
├─ models.py        NewsItem · Judgment(LLM 출력 스키마) · Plan · Leg · Campaign
├─ sources/
│   ├─ base.py      NewsSource 프로토콜 + FetchResult  (sessions/sources 와 같은 모양)
│   ├─ rss.py       Yahoo Finance 종목별 RSS · Google News 검색 RSS
│   ├─ edgar.py     SEC EDGAR 8-K/6-K 최신 공시 (Atom)  ← 공식 · 무료 · 빠름
│   ├─ finnhub.py   company-news (키 있을 때만)
│   └─ telegram.py  Telethon 사용자 세션 — 구독 채널 새 메시지
├─ tickers.py       텍스트 → 유니버스 심볼 (티커·회사명 사전, universe.py 기반)
├─ dedupe.py        URL 정규화 + 제목 유사도로 중복 제거 (같은 뉴스가 5개 소스에서 온다)
├─ store.py         DB — news_items · news_judgments · news_campaigns · news_campaign_legs
├─ collect.py       수집 루프 (th stream 안에서 돈다. 소스 하나가 죽어도 나머지는 계속)
├─ judge.py         Claude API 판단 — 프리필터 → 트리아지(저가 모델) → 본판단(구조화 출력)
├─ engine.py        NewsEngine — 새 판단 → 작전 → 가드 → 주문 / 승인 대기 · 보유 중 재평가 · 시간 만료
├─ notify.py        텔레그램 봇 — 작전 카드 전송 · 승인/거절 인라인 버튼 · 체결·청산 알림
└─ cli.py           th news ...  (collect · judge · test · campaigns · telegram-login)
```

**건드리지 않는 것**: `execution/` 의 브래킷·매니저·페이퍼·저장소. 엔진은 시그널 엔진과 똑같이
`PaperRunner.open_from_request()` 로만 주문한다. 손절 없는 주문은 여전히 타입 수준에서 불가능하다.

**가드에 추가하는 것** (`execution/guard.py`, 기존 검사는 그대로):

| 추가 | 뜻 |
|---|---|
| `GuardInput.stop_max_pct` | 요청별 손절 상한. 없으면 기존 3%. 뉴스 엔진은 5%. **절대 상한 `STOP_MAX_PCT_HARD=5.0`** 은 넘길 수 없다 |
| `GuardInput.open_notional_usdt` / `symbol_open_notional_usdt` | 이미 열린 노셔널. `(열린 + 새) ÷ 시드 ≤ EXPOSURE_LIMIT_X(3.0)`, 종목별 `≤ SYMBOL_LIMIT_X(1.0)`. 규율 지표 패널이 **보여주기만** 하던 숫자를 가드가 **막는다** |

## 3. 수집 (`th stream` 안에서)

| 소스 | 무엇 | 주기 | 인증 |
|---|---|---|---|
| 텔레그램 채널 | `TH_TELEGRAM_CHANNELS` 의 새 메시지 (푸시) | 실시간 | `TH_TELEGRAM_API_ID/HASH` + `th news telegram-login` 1회 (사용자가 직접) |
| SEC EDGAR | 유니버스 종목의 8-K·6-K 신규 공시 | 60초 | 없음 (User-Agent 필수) |
| Yahoo RSS | 종목별 헤드라인 | 120초 | 없음 |
| Google News RSS | `"<회사명>" stock` 검색 | 300초 | 없음 |
| Finnhub | company-news | 120초 | `TH_FINNHUB_API_KEY` (선택) |

- 소스는 `NewsSource` 프로토콜 (`fetch(since) -> FetchResult`). 실패는 예외가 아니라 `ok=False` 로 돌아온다. **하나가 죽어도 나머지는 돈다.**
- `dedupe_key` = 정규화 URL 이 있으면 그것, 없으면 (소스, 제목 정규화) 해시. 같은 키는 두 번 저장하지 않는다.
- 저장 시 `tickers.extract()` 로 유니버스 심볼을 붙인다. **심볼이 하나도 안 붙은 뉴스는 판단으로 보내지 않는다** (LLM 비용의 90% 를 여기서 아낀다). 단 텔레그램 메시지는 심볼이 없어도 트리아지까지는 보낸다 — 사용자가 고른 채널이라 시장 전체 뉴스가 섞여 있다.
- `data/telegram.session` 은 git 에 들어가지 않는다 (`data/` 는 이미 ignore).

## 4. 판단 (`judge.py`)

세 단계. 뒤로 갈수록 비싸다.

1. **프리필터 (무료)** — 심볼 매핑 결과가 비어 있고 텔레그램도 아니면 버린다.
2. **트리아지 (저가 모델, `TH_NEWS_TRIAGE_MODEL`, 기본 `claude-haiku-4-5`)** — `relevant / magnitude / symbols` 만. `magnitude=low` 면 여기서 끝.
3. **본판단 (`TH_NEWS_MODEL`, 기본 `claude-opus-5`, 적응형 사고)** — 구조화 출력 `Judgment`:

```jsonc
{
  "relevant": true,
  "symbols": ["NVDAUSDT"],            // 유니버스 안의 심볼만. 없으면 []
  "direction": "LONG",                // LONG | SHORT | NONE
  "confidence": 0.82,                 // 0~1. TH_NEWS_MIN_CONFIDENCE(0.70) 미만이면 관찰만
  "magnitude": "high",                // low | medium | high
  "horizon_hours": 48,                // 1~168
  "thesis_ko": "…왜 이 방향인가 (3문장 이내)",
  "risks_ko": ["…", "…"],
  "already_priced_in": false,         // 뉴스 시각 대비 현재가가 이미 움직였으면 true → NONE
  "plan": {
    "stop_pct": 3.0,                  // 가격 기준 1~5. 가드가 다시 자른다
    "target_pct": 5.0,                // 가격 기준. 마진 +50% = 가격 +5% (10배)
    "tp2_pct": null,
    "max_hold_hours": 72,
    "legs": [                         // 1~3개. margin_pct 합계 ≤ TH_NEWS_MARGIN_PCT_MAX(10)
      {"margin_pct": 4, "entry": "market", "limit_offset_pct": null, "expire_hours": 0.1},
      {"margin_pct": 3, "entry": "limit",  "limit_offset_pct": -1.5, "expire_hours": 24},
      {"margin_pct": 3, "entry": "limit",  "limit_offset_pct": -3.0, "expire_hours": 24}
    ],
    "invalidation_ko": "…어떤 일이 생기면 계획이 틀린 것인가"
  }
}
```

입력에 넣는 것: 뉴스 원문(제목·본문·소스·시각), 매핑된 심볼의 **현재가·24h 변동·뉴스 시각 이후 변동**(이미 반영됐는지 판단용), 세션 레짐(프리/본장/애프터/휴장)과 다음 이벤트, 같은 종목의 최근 24h 뉴스 요약, 열린 작전. **원시 캔들은 주지 않는다** (docs/06 E.1 원칙).

시스템 프롬프트 + 유니버스 목록은 고정이라 **프롬프트 캐시**를 건다. 뉴스 본문은 그 뒤에 온다.
모든 호출의 `usage` 를 `news_judgments.usage` 에 남겨 비용을 화면에서 본다.

`stop_reason == "refusal"` 이나 파싱 실패는 `error` 로 기록하고 그 뉴스는 건너뛴다. 판단이 없으면 매매도 없다 — 조용히 기본값으로 진입하지 않는다.

## 5. 작전 (Campaign) 과 실행 (`engine.py`)

- 작전 = 종목 하나 · 방향 하나 · 다리(leg) 1~3개. 다리 하나 = 브래킷 하나 (`setup_id = "news_event"`).
  같은 손절·같은 목표, 진입만 다르다 (시장가 / 지정가 오프셋). 지정가 다리의 만료는 `expire_hours`.
- **크기 계산**: `notional_x = margin_pct / 100 × TH_NEWS_LEVERAGE(10)`. 러너의 수량 역산에 맞춰
  `risk_pct = stop_pct × notional_x` 로 넘긴다 (시그널 엔진과 같은 변환). 예: 마진 4% · 손절 3% → 노셔널 0.4배, 위험 시드의 1.2%.
- **같은 종목에 열린 작전이 있으면 새 작전은 열지 않는다.** 대신 새 뉴스로 **재평가**한다: 판단이 반대 방향·`magnitude=high` 면 `close_now` (사유 `NEWS_REVERSAL`) 하고 알린다. 청산은 위험을 줄이는 쪽이라 승인 없이 한다.
- 시간 만료: `max_hold_hours` 를 넘기면 `close_now(reason="TIME")`.
- 세션 게이트: 기존 `session_gate()` 그대로 — 본주 정지 시간(20:00~04:00 ET·주말) 에는 **진입** 안 한다. 보유는 넘어간다 (주말 진입 60분 전 경고는 알림으로 전달).
- 시세: 수집 종목(`TH_SYMBOLS`)이 아니면 페이퍼 체결 판정용 시세가 없다. 엔진이 여는 종목은 **공개 REST `bookTicker` 폴백**으로 시세를 먹인다 (`execution/quotes.py` 확장, 3초). 60종목 전부를 `th stream` 에 넣는 건 스트림 수 문제라 하지 않는다.

### 실행 모드 (`TH_NEWS_EXEC`)

| 값 | 동작 |
|---|---|
| `observe` | 수집·판단만. 작전은 `proposed` 로 기록되고 주문 없음 |
| `paper` (기본) | 확신도 ≥ 임계값이면 **바로 페이퍼 주문**. 텔레그램으로 카드만 보낸다 |
| `approve` | 카드를 보내고 **승인 버튼을 누른 것만** 페이퍼 주문. 실거래 흐름의 리허설. 미승인은 `TH_NEWS_APPROVAL_TTL_MIN`(30분) 뒤 `expired` |
| `live` | **아직 없다.** `live.py` 가 열리기 전엔 설정해도 `approve`+페이퍼로 동작하고 경고 로그 |

## 6. 알림·승인 (`notify.py`)

텔레그램 봇 (`TH_TELEGRAM_BOT_TOKEN`, `TH_TELEGRAM_CHAT_ID`). 사용자 세션과는 별개.

- 작전 카드: 종목 · 방향 · 확신도 · 근거 3줄 · 다리별 크기/진입 · 손절/목표/최대보유 · 뉴스 링크 · `[승인] [거절]`
- 체결·손절·익절·시간만료·뉴스반전 청산 알림
- 하루 1회 요약 (작전 수 · 승률 · 누적 R · API 비용)
- 승인은 `callback_query` 를 long-poll 로 받는다. `TH_TELEGRAM_CHAT_ID` 외에서 온 버튼은 무시.
- 봇이 죽어도 엔진은 돈다 (`paper` 모드). `approve` 모드에서 봇이 죽으면 **아무것도 열지 않는다** — 모르면 막는다.

## 7. 화면 (`/news`)

헤더 탭에 `뉴스` 추가. 왼쪽: 수집 피드(소스·시각·심볼·판단 칩). 오른쪽: 작전 목록(상태·다리·R) + 상세(판단 JSON 사람이 읽게, 뉴스 원문 링크) + 엔진 상태(모드·마지막 수집·오늘 API 비용) + 웹 승인 버튼(텔레그램과 같은 경로).
매매기록 페이지의 `자동` 탭에 `setup_id=news_event` 가 합쳐진다.

## 9. 지키는 규칙 (테스트로 고정)

- 판단 없이는 주문 없다. LLM 오류·거절·파싱 실패 → 건너뜀 (기본값 진입 금지)
- 작전 마진 합계 ≤ `TH_NEWS_MARGIN_PCT_MAX`, 손절 ∈ [1, 5], 노출 합계 ≤ 3.0배, 종목 ≤ 1.0배 — **가드가** 막는다 (엔진 코드가 아니라)
- `approve` 모드에서 승인 없이 열린 브래킷이 있으면 테스트 실패
- 봇 승인은 `TH_TELEGRAM_CHAT_ID` 에서 온 것만
- 하루 API 비용 상한을 넘기면 판단을 멈춘다 (수집은 계속)
- 화면·알림에 "매수 추천" 류 문구 없음. 라벨은 "엔진 판단"
