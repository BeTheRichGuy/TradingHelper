# 13 — AI 트레이딩 조사 · 우리 프로그램의 방향

조사일: 2026-09-09 · 전제: 바이낸스 SOXLUSDT 10배 선물, 5분봉, 개인 봇

---

## 0. 한 줄 결론

**LLM 이 방향을 맞히게 하는 건 우리가 이미 기각한 길이다.**
하지만 **LLM 이 "지금은 하지 마"를 판단하게 하는 건 우리가 이미 성공한 길이다.**

`docs/08` 에서 세션 게이트만 유일하게 값을 했다 — 차단한 신호 −0.462R vs 허용한 신호
−0.177R. 가격 정보로 만든 필터(ADX·ER·교차·일봉 모멘텀)는 **전부** 실패했는데,
**시간·이벤트 정보로 만든 필터는 성공했다.** LLM 의 강점이 정확히 그 자리에 있다.

## 1. 링크의 AI-Trader — 실제 숫자

[HKUDS/AI-Trader](https://github.com/HKUDS/AI-Trader) 는 GPT·Claude·Qwen·DeepSeek·Gemini 가
같은 조건에서 나스닥100 종목을 거래하며 겨루는 오픈소스 실험이다 (MIT, MCP + LangChain).

[실험 결과](https://blog.solarstar.app/posts/ai-trade.en/):

| 모델 | 수익률 |
|---|---|
| DeepSeek | **+9.68%** |
| Claude-3.7 | +2.17% |
| GPT-5 | +1.60% |
| **QQQ (벤치마크)** | **+1.22%** |
| Qwen3-max | −0.75% |
| Gemini-2.5 | −2.73% |

**이 표를 읽는 법이 중요하다.** 기간이 **1개월 미만**이고 모델이 5개다.
5개를 한 달 돌리면 그중 하나는 벤치마크를 크게 이긴다 — 우연히.

우리가 `docs/11` 에서 SOXL 로 겪은 것과 **정확히 같은 구조**다.
34종목을 돌려 1개가 좋아 보였고, 계산해보니 우연이 예측한 개수(1.15개)와 같았다.

저자도 한계를 명시했다 — "1개월은 너무 짧다", "약세장 미검증", "종이거래".

## 2. 학계 벤치마크가 말하는 것

### StockBench ([arXiv 2510.02209](https://arxiv.org/abs/2510.02209))

> "most models struggle to outperform the simple buy-and-hold baseline"

그리고 핵심 관찰: **정적 금융 QA 성능이 실제 거래 행동으로 번역되지 않는다.**
"재무제표를 잘 읽는 것"과 "언제 사고 팔지 아는 것"은 다른 능력이다.

### KTD-Fin ([arXiv 2605.28359](https://arxiv.org/html/2605.28359v1))

2024-01 ~ 2026-04, CSI300 대비:

| 모델 | 총수익 | 초과수익 | 샤프 | 최대낙폭 |
|---|---|---|---|---|
| Qwen3.6-plus | +85.29% | +48.37% | 1.13 | −24.49% |
| GPT-5.5 | +61.26% | +24.34% | 0.98 | −24.63% |
| Claude-opus-4-7 | +58.80% | +21.88% | 0.98 | −26.69% |
| CSI300 | +36.92% | — | — | — |

숫자만 보면 압승이다. **그런데 저자들이 Barra 스타일 분해를 돌렸다:**

> **"대부분의 LLM 에이전트 수익이 시장 베타와 스타일 노출로 설명되며,
> 주식 선택 알파는 대부분 음수였다."**

즉 **초과수익이 실력이 아니라 노출**이었다. 고베타 종목을 많이 들고 있었을 뿐이다.
우리가 BTC 시계열 모멘텀에서 "매수후보유를 못 이긴다"고 판정한 것과 같은 종류의 발견이다.

**더 결정적인 실험 하나**: 티커를 익명화(blinded)하자 모델들이 **거래를 아예 멈췄다**(현금 100%).
종목 이름을 보고 "방어주 우량주", "주도종목" 같은 브랜드 지식으로 판단하고 있었다는 뜻이다.
분석이 아니라 **암기**였다.

그리고 백테스트 548거래일의 대부분이 모델 학습 시점과 겹친다 — 데이터 오염 가능성.

## 3. 왜 이게 우리 케이스로 전이되지 않는가

위 연구들이 다루는 게임과 형이 하는 게임이 다르다.

| | 연구들 | 형의 매매 |
|---|---|---|
| 대상 | 나스닥100 · CSI300 **수십~수백 종목** | **SOXLUSDT 하나** |
| 판단 | 어느 종목을 살까 (**횡단면 선택**) | 지금 살까 말까 (**타이밍**) |
| 주기 | 일 단위 이상 | **5분봉** |
| 근거 | 뉴스·재무제표·애널리스트 | 가격·거래량 |
| 레버리지 | 1배 | **10배** (SOXL 3배 × 10 = 지수 30배) |

**핵심 차이 두 개:**

**① 종목이 하나면 LLM 이 잘하는 일이 없어진다.** 위 연구들의 LLM 은 "수백 개 중 뭘 고를까"를
한다. SOXL 하나만 보면 고를 게 없다. 남는 건 타이밍인데, 우리는 그 타이밍에
정보가 없다는 걸 **15,458건**으로 측정했다 (`docs/11`).

**② LLM 은 가격 차트에서 미래를 못 본다.** 우리는 240차원 패턴 검색(k-NN)까지 해봤고
셔플 대조군에 졌다(p=0.92). 같은 가격 데이터를 LLM 에게 그림이나 숫자로 줘도
없는 정보가 생기지 않는다. 오히려 LLM 은 **아무 차트에나 그럴듯한 이야기를 만들어낸다** —
확신은 올라가는데 확률은 그대로다. 10배에서 제일 위험한 조합이다.

## 4. 그런데 AI 가 진짜로 값을 하는 자리가 있다

우리 측정에서 **유일하게 성공한 필터**를 다시 보자.

```
가격으로 만든 필터    ADX · 효율성비율 · EMA99 교차 · 일봉 모멘텀   → 전부 실패
시간·이벤트 필터      세션 게이트                                   → 성공
                     차단한 신호 −0.462R  vs  허용한 신호 −0.177R
```

**우리가 4일 동안 쓴 데이터가 100% OHLCV 였다.** 뉴스·실적·FOMC·공급망·관세는
손도 안 댔다. 그게 유일하게 안 파본 정보축이고, 하필 **LLM 이 제일 잘하는 것**이다.

### 그래서 방향은 "예측"이 아니라 "차단"이다

| 하지 말 것 | 할 것 |
|---|---|
| "지금 롱? 숏?" 을 LLM 에게 묻기 | "지금 기술적 분석이 통하지 않는 상황인가?" 를 묻기 |
| 차트 이미지를 주고 판단시키기 | 뉴스·이벤트를 **분류**시키기 (판단 아님) |
| 승률을 생성하게 하기 | 근거를 기록하게 하기 |

`docs/06` D모듈에 이미 설계해둔 그대로다 — LLM 은 헤드라인을 받아
`{relevant, affected, polarity, magnitude, expected_duration}` 으로 **분류만** 한다.
`magnitude: high` 가 30분 안에 들어오면 신규 진입을 차단한다.

**뉴스가 방향을 정해주지 않는다. 뉴스는 "지금 TA 가 안 통한다"는 신호로만 쓴다.**

이건 검증도 쉽다. 우리가 만든 `th gate-value` 가 정확히 이걸 잰다 —
차단한 신호가 통과한 신호보다 실제로 나빴는가.

### 두 번째 자리 — 사후 분석 (지금 당장 값어치 있음)

업계가 실제로 가는 방향이 **"완전 자동화가 아닌 감시된 자동화"**다
([Copilot & Agentic Execution](https://openwebsolutions.in/blog/ai-in-stock-trading-software-copilots-agentic-execution/)):

- Copilot = 자연어로 묻고 답하는 **분석 레이어**
- Agentic execution = 사람이 의도를 정하고 **AI 는 실행 세부만** 관리
- 필수: 모든 권고의 로그·감사 추적, 휴먼 오버라이드, 긴급 정지

우리한테 이게 바로 쓰인다. `th journal` 로 형의 매매가 쌓이면 LLM 이:
- "이 이유로 잡은 것들만 모아서 성적 비교"
- "손절이 자주 걸린 시간대·상황 패턴"
- "형이 적은 이유와 실제 결과의 괴리"

를 정리해준다. **형의 판단을 대체하는 게 아니라 형의 기록을 읽는 것**이라
없는 알파를 지어낼 위험이 없다.

## 5. 구현 가능성 — 개인 봇으로 되나

**된다. 어렵지 않다.** 비싼 것도 아니다.

| 항목 | 수치 |
|---|---|
| 호출 빈도 | 5분봉 마감마다 1회 = 본장 78회/일 |
| 지연 | 2~5초 (비동기로 처리하면 신호를 막지 않음) |
| 비용 | 호출당 약 $0.01~0.05 → **월 $30~100** |
| 뉴스 소스 | Finnhub 무료 티어 (`docs/06` D.1 에 이미 조사됨) |
| 이미 있는 것 | 세션 게이트, `th gate-value` 검증 도구, 스키마, 숫자 검증 폴백 |
| 새로 만들 것 | 뉴스 수집기 + LLM 분류기 + 게이트 피드백 |

**난이도는 2~3일치 작업**이다. `docs/06` 에 설계가 이미 다 되어 있다.

### 반드시 지켜야 할 것 (`docs/06` E.2·E.4 에 이미 적어둔 것)

1. **LLM 에게 원시 차트·캔들을 주지 않는다.** 구조화된 숫자만 준다
2. **LLM 이 숫자를 만들지 못하게** 한다 — 생성된 텍스트의 모든 숫자를 입력 JSON 과 대조,
   없는 숫자가 나오면 템플릿 문장으로 폴백
3. **방향을 단정하지 않게** 한다 — "오를 것" 이 아니라 "두 모델 모두 상승 쪽"
4. **차단에만 쓰고 발행에는 쓰지 않는다** — `th gate-value` 로 검증하기 전까지

## 6. 제품 방향 제안

지금까지 측정한 것 위에서, 이 앱이 실제로 팔 수 있는 가치는 **"예측"이 아니라 "보호와 규율"**이다.

```
① 안전장치      청산 거리 · 손절 누락 · 일일 한도 · 세션 차단     ← 이미 있음, 검증 불필요
② AI 차단 레이어  뉴스·이벤트로 "지금은 하지 마"                  ← 다음에 만들 것
③ 실행 품질      지정가 체결로 비용 절반 · 사이징 자동 계산        ← 실행 계층에 있음
④ 사후 분석      형의 매매 기록을 AI 가 읽고 패턴을 찾아줌         ← journal 위에 얹으면 됨
⑤ 방향 제시                                                    ← 우위를 찾기 전까지 없음
```

**⑤가 없어도 ①~④는 팔린다.** 오히려 시장에 널린 게 ⑤(승률 몇 % 신호)이고,
그게 대부분 검증 안 된 마케팅이다. `docs/11` 같은 판정 문서를 붙여서
"우리는 우위가 없으면 없다고 말한다"가 차별점이 될 수 있다.
