작성일: 2026-08-29 · Phase 0 착수 시점에 내린 결정 기록

로컬 PC에서 무료로 시작하되, 나중에 ① 도쿄 VPS 이전 ② 자동매매 ③ 다른 사용자에게
유료 제공으로 넘어갈 때 구조를 갈아엎지 않도록 지금 깔아둔 것들.

## 1. 로컬 → 도쿄 VPS 이전 — 30분~1시간

**어렵지 않다.** Phase 0 코드가 이미 그 전제로 쓰여 있다.

### 이전 절차 전부

```bash
# VPS에서
git clone <저장소> && cd trading-helper
# .env 를 복사하거나 새로 작성  (TH_ENV=vps 로만 바꾸면 됨)
docker compose --profile server up -d --build
```

**코드는 한 줄도 고치지 않는다.** 데이터를 옮기려면 `pg_dump` 한 번, 아니면
VPS에서 `th backfill --full` 로 다시 받으면 된다.

### 그렇게 만든 장치

| 장치 | 없었다면 생겼을 문제 |
|---|---|
| 설정을 전부 `.env` 환경변수로 | 호스트명·비밀번호가 코드에 박혀 파일마다 찾아 고쳐야 함 |
| 처음부터 Postgres 컨테이너 (SQLite 아님) | SQLite→Postgres 마이그레이션은 스키마·쿼리를 다 손봐야 함 |
| `docker-compose.yml` 하나를 로컬·VPS 공용 (VPS는 `--profile server` 추가) | 환경마다 설정 파일이 갈라짐 |
| 모든 시각을 UTC로 저장 | 서버 타임존이 달라 봉 시각이 어긋남 |
| 상태를 전부 DB 안에 (로컬 파일 없음) | 옮길 때 뭘 챙겨야 할지 모름 |

### 언제 옮겨야 하나

지금(전략이 되는지 확인하는 단계)은 로컬로 충분하다. 아래 중 하나라도 해당되면 그때 옮긴다.

1. **PC를 끄는 동안 데이터에 구멍이 생기기 시작할 때** — 백테스트 표본이 그만큼 준다
2. **읽기 전용 API 키를 붙일 때 (Phase 2)** — IP 화이트리스트를 걸려면 고정 IP가 필요하다
3. 실시간 신호를 켜둔 채 매매하고 싶을 때

→ **Phase 2 진입 시점이 자연스러운 이전 시기.** 그 전까지 비용 0원.

## 2. 자동매매 확장

### 지금 깔아둔 것

`src/th/exchange/base.py`:

```python
class ExecutionClient(Protocol):
    async def submit(self, req: OrderRequest) -> OrderResult: ...
    async def cancel(self, symbol: str, order_id: str) -> OrderResult: ...

class NoopExecutor:          # 현재 유일한 구현 — 호출되면 항상 거부
    mode = "none"
```

- 전략 코드는 **주문 API를 직접 호출하지 않는다.** 항상 이 인터페이스를 거친다.
- `TH_EXECUTION_MODE` 가 `paper`/`live` 면 **지금은 즉시 `NotImplementedError`로 죽는다.**
  반쯤 만들어진 주문 코드가 조용히 도는 것보다 낫다.

### 붙일 때 하는 일

1. `PaperExecutor` — 실제 주문 없이 체결을 시뮬레이션하고 `signals`/`journal`에 기록
2. `BinanceExecutor` — 실주문. 새 API 키(거래 권한 O, **출금 권한 X**)를 별도 발급
3. `TH_EXECUTION_MODE` 변경

### 실전 주문을 켜기 전 반드시 충족할 조건

| # | 조건 | 현재 |
|---|---|---|
| 1 | Phase 4 백테스트 통과 (out-of-sample 기대값 ≥ +0.20R) | **❌ 불합격 (2026-09-08)** |
| 2 | Phase 5 이후 **4주 이상 실시간 관찰**, 표시 승률 vs 실제 승률 괴리 10%p 이내 | 미착수 |
| 3 | `PaperExecutor` 로 4주 이상 무사고 | 미착수 |
| 4 | 킬스위치: 일일 −3R, 연속 손절, 데이터 지연, WS 끊김 → **자동으로 주문 중단** | 미착수 |
| 5 | 주문 API 키에 출금 권한 없음 + IP 화이트리스트 | 미착수 |
| 6 | 모든 주문 전 손절 주문이 같이 나가는 구조 (진입만 나가고 손절이 빠지는 경로가 없을 것) | 미착수 |

> 10배 레버리지 자동매매에서 버그 하나는 즉시 실손실이다. 위 6개는 타협 대상이 아니다.

### ⛔ 자동매매는 현재 **불가**입니다 (2026-09-08)

1번이 불합격입니다. 셋업에 방향성 우위가 확인되지 않았습니다
(`08-전략-검증-결과.md`). **우위가 없는 전략을 자동화하면 손실만 자동화됩니다.**

기대값 −0.14R 짜리를 자동으로 하루 10번 돌리면 하루 −1.4R, 한 달이면 −30R 입니다.
계좌 10,000 USDT · 리스크 0.5% 기준으로 **한 달 −1,500 USDT**. 사람이 하면 중간에
멈추지만 자동은 안 멈춥니다.

`TH_EXECUTION_MODE` 는 `none` 그대로 두고, `th.account` 에 주문 코드는 계속
없습니다. 1번을 통과하기 전에는 2~6번을 만들 이유도 없습니다.

## 3. 다른 사용자에게 유료 제공

### 지금 깔아둔 것

| 항목 | 현재 |
|---|---|
| `users` 테이블 | 존재. 소유자 1명이 들어가 있음 |
| `users.plan` | `owner` / `free` / `pro` — 플랜별 제한을 읽을 자리 |
| `TH_OWNER_ID` 설정 | 사용자 귀속 데이터가 이 ID로 들어감 |
| 시세 데이터에 `owner_id` 없음 | **의도적.** 시세는 모두가 공유하므로 멀티유저가 돼도 그대로 |

### 나중에 추가할 것

1. 인증 (Supabase Auth 또는 Clerk) + 사용자별 테이블에 `owner_id` 적용
2. 사용자별 바이낸스 API 키 저장 — **평문 저장 절대 금지.** KMS/Vault 또는 앱 레벨 암호화
3. 요금제별 제한 (심볼 수, 갱신 주기, AI 브리핑 횟수)
4. 결제 (Stripe / 토스페이먼츠)
5. 사용자 수에 따라 WS 팬아웃 분리 — 수집 워커 1개가 모두에게 브로드캐스트하는 구조라 확장이 쉬움

### ⚠️ 먼저 확인해야 할 것 — 기술이 아니라 규제

한국에서 **불특정 다수에게 대가를 받고 투자 판단 정보를 제공**하는 사업은
자본시장법상 유사투자자문업 신고 대상이 될 수 있고, 개별 상담까지 하면
투자자문업 등록 문제로 넘어간다. 파생상품·해외 거래소가 얽히면 더 복잡하다.

> **2026-09-08 갱신 — 지금은 이 문제가 잠시 비켜갔습니다.**
>
> Phase 4 판정으로 **방향(매수/매도)을 제시하는 기능 자체를 뺐습니다.** 남은 것은
> 청산가 거리·손절 누락 경고·세션 시간대 표시 — **사실 조회이지 투자 판단이
> 아닙니다.** 그래서 지금 형태 그대로라면 유사투자자문 논점에서 멀어집니다.
>
> 다만 **신호 기능을 되살리는 순간 이 문제가 그대로 돌아옵니다.** 그때는 아래
> 순서대로 확인해야 하고, 그전에 유료화를 시작하면 안 됩니다.

**코드를 짜기 전에 확인할 순서:**

1. 유료화 계획이 구체화되면 **금융 규제 전문 변호사 상담** (저는 변호사가 아니고, 이건 법률 자문이 아니다)
2. 서비스 문구를 "추천"이 아니라 "정보 제공"으로 일관되게 정리
3. 이용약관·면책 조항
4. 개인 API 키를 대신 보관하는 순간 보안 책임이 크게 올라간다는 점 인지

기술 확장은 어렵지 않다. **이쪽이 실제 병목이다.**

## 4. 지금은 하지 않기로 한 것

조기 확장은 비용만 든다. 다음은 **의도적으로 미뤘다.**

| 안 하는 것 | 이유 | 필요해지는 시점 |
|---|---|---|
| Kubernetes / 오토스케일 | 사용자 1명 | 동시 사용자 수백 명 |
| 마이크로서비스 분리 | 하나의 compose로 충분 | 수집과 분석의 부하가 갈릴 때 |
| 인증·권한 시스템 | 혼자 씀 | 두 번째 사용자 |
| 사용자별 키 암호화 저장 | 내 키는 서버 `.env` 에만 | 남의 키를 받는 순간 |
| CI/CD | 로컬에서 직접 실행 | VPS 이전 시 |
| `aggTrade` 초 단위 수집 | 디스크만 먹음. 1분 CVD는 봉의 taker_buy_base로 충분 | 초 단위 델타가 필요해질 때 |

## 5. 지키기로 한 규칙 (앞으로 코드 리뷰 기준)

1. **비밀값은 코드·DB·클라이언트에 절대 두지 않는다.** 서버 환경변수만.
2. **모든 시각은 UTC로 저장한다.** 표시할 때만 KST로 바꾼다.
3. **전략 코드는 거래소 API를 직접 호출하지 않는다.** 항상 프로토콜 경유.
4. **`none` 이외 실행 모드는 명시적으로 켜야 하고, 미구현이면 즉시 실패시킨다.**
5. **새 설정값은 반드시 `.env.example` 에 추가한다.** 그래야 이전할 때 빠지지 않는다.
