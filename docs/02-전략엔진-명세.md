## 5. 리스크 계산 — 이 문서에서 가장 중요한 절

### 5.1 진입 구간과 기준 진입가

진입가는 단일 값이 아니라 **구간**(`entry.low`, `entry.high`)으로 제시한다. 실제 체결이 그 안 어디서 될지 모르기 때문이다.

```
기준 진입가 = 롱이면 entry.high,  숏이면 entry.low
```

**최악의 체결가를 가정한다.** 롱을 구간 상단에서 잡았다고 보면 1R이 커지고, 그 결과 포지션은 작아지고 목표는 멀어진다 — 셋 다 보수적인 방향이다. 반대로 잡으면 실제보다 리스크를 작게 보고 사이즈를 키우게 된다.

### 5.2 손절가

```
ATR_pct   = ATR(1m, 14) / 현재가
SL_dist   = clamp(1.5 × ATR_pct, 0.50%, 1.00%)
구조적_SL  = 최근 15개 1분봉 안의 스윙 저점 − 0.2 × ATR      (롱)
손절가     = min(기준진입가 × (1 − SL_dist), 구조적_SL)      (롱, 더 넓은 쪽)
```

하한 0.50%: 이보다 좁으면 스프레드+슬리피지에 걸려 무의미하게 털린다.
상한 1.00%: 이보다 넓으면 TP1(=2R)이 본주 2% 목표를 넘어간다.

**이 두 숫자는 5.3의 발행 조건과 같은 값에서 파생된다** — 클램프가 통과시킨 손절이
발행에서 거부되는 죽은 구간이 생기면 안 된다. (v0.1 에서는 클램프가 [0.30, 0.70],
발행이 [0.40, 0.625] 라 어긋나 있었고, 실측 결과 리스크 단계 탈락의 **91%**가
거기서 나왔다.)

**구조 탐색 창이 15봉인 이유**는 S1 의 정의가 "최근 3개의 5분봉(=15분) 안의 되돌림"
이기 때문이다. 셋업이 틀렸다고 판정되는 지점은 그 되돌림의 저점이지 한 시간 전
피벗이 아니다. 창을 60봉으로 뒀을 때 손절 중앙값이 0.70% → **1.38%** 로 벌어졌다.

숏은 부호 반전, `max` 사용.

### 5.3 익절가 — 사용자 목표(본주 1~2%)에 맞춤

```
1R  = |기준 진입가 − 손절가|

TP1 = 기준진입가 ± 2.0R      (포지션 50% 청산, 손절을 본전으로 이동)
TP2 = 기준진입가 ± 4.0R

발행 조건: TP1 ≥ 1.0%  AND  4R ≤ 4.0%
```

**이 숫자는 사용자 목표에서 역산한 것이다.**

```
목표: 본주 1~2% = 포지션 10~20%  →  그게 TP1 이다
TP1 = 2R ∈ [1.0%, 2.0%]         →  R ∈ [0.50%, 1.00%]   ← 5.2의 클램프
TP2 = 4R ∈ [2.0%, 4.0%]
```

SL 0.6%면 TP1 +1.2%(포지션 +12%), TP2 +2.4%(포지션 +24%) — 목표 밴드 한가운데다.
SL 1.0%면 TP1 +2.0%(포지션 +20%) — 목표 밴드 상단이다.

**예상 소요 시간**은 공식으로 추정하지 않는다. 백테스트에서 같은 셋업·같은 세션의 TP1 도달 시간 **중앙값**을 그대로 표시한다 (예: "중앙값 22분, 사분위 11–41분").

### 5.4 포지션 사이즈 — 레버리지로 계산하지 않는다

```
명목가 = (계좌잔고 × 리스크비율) / SL_dist
수량   = floor(명목가 / 기준진입가)
```

기본 리스크비율 **0.5%** (10배 데이트레이딩에서는 1%도 공격적이다). 설정에서 0.25~1.5%.

**여기서 나오는 숫자는 아마 지금 쓰시는 사이즈보다 훨씬 작다.** 그 이유를 명확히 해두는 게 중요하다.

```
계좌 10,000 USDT · 리스크 0.5% · 손절 0.6%
  → 명목가 = 50 / 0.006 = 8,333 USDT  (계좌의 0.83배)
  → 10배 증거금 기준 실제 묶이는 돈은 833 USDT

같은 계좌를 10배 풀사이즈(명목 100,000)로 쓰면
  → 손절 0.6% 한 번 = 600 USDT = 계좌의 6%
  → 연속 5회 손절 = 계좌의 30% 증발
```

**레버리지 배수는 사이즈를 키우는 손잡이가 아니라 청산가를 정하는 손잡이다.** 같은 명목가라면 레버리지를 낮게 잡을수록 증거금이 많이 잡히고 청산가가 멀어진다. 사이즈는 항상 손절 거리에서 역산하고, 레버리지는 청산 여유를 확보하는 쪽으로 고른다.

### 5.5 청산 안전거리

```
MMR      = 바이낸스 leverageBracket API에서 조회 (심볼·명목가별로 다름)
청산거리  = 1/레버리지 − MMR            (격리마진 기준, 롱)
         = 1/10 − 0.005 = 9.5%

안전 규칙: SL_dist ≤ 청산거리 × 0.35
```

**현실 점검:** 위 손절폭(0.3~0.7%)은 청산거리 9.5%에 한참 못 미치므로 이 규칙은 평소엔 걸리지 않는다. **10배에서 계좌가 죽는 경로는 손절폭이 넓어서가 아니라 다음 셋 중 하나다.**

| 죽는 경로 | 앱의 방어 |
|---|---|
| ① 손절 주문을 안 넣음 | 읽기전용 API로 `openOrders` 조회 → **포지션은 있는데 STOP 주문이 없으면 화면 전체 빨간 경고** |
| ② 이벤트 갭 — 손절가를 건너뛰고 체결 | 세션·이벤트 게이트(05 문서)로 진입 자체를 막음. 보유 중이면 이벤트 D-day 경고 |
| ③ 손절 후 물타기 / 연속 손절 | 일일 손실 한도 (5.6절) |

### 5.6 일일 손실 한도

```
당일 누적 −3R 도달  → 신호 발행 중단, 대시보드 전체에 "오늘 종료" 표시
연속 3회 손절       → 60분 쿨다운
```

10배에서 연속 손절은 계좌를 빠르게 태운다. 이 락은 사용자가 끌 수 없게 만든다 (다음 날 00:00 KST 자동 해제).

### 5.7 펀딩 비용 반영

```
예상 보유시간이 다음 펀딩 정산을 넘으면:
  예상 펀딩비용 = |펀딩률| × 명목가   → 신호 카드에 표시
펀딩률 절대값 > 0.05%:
  같은 방향 진입 시 신뢰도 −10 (쏠림 = 청산 사냥 대상)
```

## 6. 신뢰도 점수

```
raw     = Σ(충족된 선택 조건 가중치)
max     = Σ(해당 셋업 선택 조건 전체 가중치)     ← 필수 조건은 분모에 없음
base    = round(raw / max × 100)
score   = clamp(base + 세션보너스 − 세션페널티 + OI보정 + 펀딩보정 + AI보정, 0, 100)
```

- 필수 조건 미충족 → 평가 중단, 점수 계산 안 함
- `score < 55` → 발행 안 함
- 55~69 "약함" / 70~84 "보통" / 85+ "강함"
- **점수는 승률이 아니다.** 승률은 7절, 확률은 06 문서에서 별도로 나온다. UI에서 셋을 분리 표시한다.

## 7. 승률 — 백테스트로만 산출

### 7.1 백테스트 규칙

1. 데이터: 바이낸스 SOXLUSDT 1분봉 (상장 이후 전 구간) + 본주 SOXL 1분봉 + OI/펀딩 히스토리
2. 신호 봉 다음 봉 시가 체결
3. 같은 봉에서 SL·TP 동시 터치 → **SL 우선**
4. 비용: 왕복 수수료 0.08% (taker) + 슬리피지 0.03% + 해당 구간 펀딩
5. 종료: TP1 후 본전손절 → TP2 / SL / 240봉(4시간) 경과 시 청산

### 7.2 "승리" 정의

> **승리 = 모든 비용 차감 후 최종 손익 > 0**

### 7.3 표시 단위

**셋업 × 세션레짐 × 신뢰도구간**으로 쪼개서 집계한다. 세션을 안 나누면 숫자가 무의미해진다.

```
승률       = 승리 / 전체
신뢰구간   = Wilson 95%
기대값(R)  = 승률 × 평균이익R − (1−승률) × 평균손실R
```

- 표본 < 50 → 승률 숨김, "표본 부족 (n=23)"
- 표시 예: **승률 57% (n=186, CI 50–64%) · 기대값 +0.51R · TP1 중앙 22분**

### 7.4 검증 구간

| 구간 | 용도 |
|---|---|
| 상장~6개월 전 | 파라미터 튜닝 (in-sample) |
| 최근 6개월~1개월 | 검증 (out-of-sample) — 여기서 깨지면 폐기 |
| 최근 1개월 | 워크포워드 |

**표시 승률은 out-of-sample 이후 구간에서만 계산한다.**

> ⚠️ 주식 perp은 상장된 지 오래되지 않아 히스토리가 짧다. 표본이 부족하면 승률을 표시하지 않고, 대신 06 문서의 유사 패턴 검색 결과를 본주(SOXL) 장기 1분봉으로 대체 산출한다.
