# 세션 · 이벤트 타임맵

작성일: 2026-08-29

> "장이 바뀌는 시간이나 특정 시간에 기술적 분석과 의미없이 차트가 움직인다" — 이 문서는 그 시간들을 전부 코드가 아는 형태로 옮긴 것이다. 전략 엔진은 셋업을 평가하기 **전에** 먼저 이 표를 조회한다.

---

## 1. 시간 처리 규칙

- 내부 저장·계산은 **전부 UTC**. 표시만 KST.
- 미국 시장 시각 판정은 `America/New_York` 타임존으로 하고, 서머타임(DST)은 라이브러리(`zoneinfo` / `pandas_market_calendars`)에 맡긴다. **직접 계산하지 않는다.**
- 미국 DST: 3월 둘째 일요일 ~ 11월 첫째 일요일. 2026년은 **3/8 ~ 11/1**.
- 한국은 DST가 없으므로 **한국시각 기준 개장 시각이 1년에 두 번 1시간씩 밀린다.** 사용자에게 매우 헷갈리는 지점이라, 대시보드 세션 배너는 항상 KST 절대 시각과 남은 시간을 같이 보여준다.

```
서머타임(EDT, 3~11월): KST = ET + 13시간
표준시(EST, 11~3월):   KST = ET + 14시간
```

## 2. 4대 레짐

| 레짐 | ET | KST (서머타임) | KST (표준시) | 특징 |
|---|---|---|---|---|
| 🟡 `PRE` 프리장 | 04:00–09:30 | 17:00–22:30 | 18:00–23:30 | 거래량 적음. 08:30 지표에 급변. 갭 형성 구간 |
| 🟢 `RTH` 본장 | 09:30–16:00 | 22:30–05:00 | 23:30–06:00 | 진짜 가격 발견. 기술적 분석이 작동하는 유일한 구간 |
| 🟠 `POST` 애프터 | 16:00–20:00 | 05:00–09:00 | 06:00–10:00 | 실적 발표 반응. 유동성 급감, 슬리피지 확대 |
| 🔴 `CLOSED` 언더라잉 정지 | 20:00–04:00 · 주말 · 미국 공휴일 | 09:00–17:00 | 10:00–18:00 | perp 단독 가격. 아래 3절 참조 |

### 반휴장일 (13:00 ET 조기 마감)

추수감사절 다음날, 크리스마스 이브, 7월 3일 등. 이날은 **13:00 ET에 🟢가 끝나고 🔴가 훨씬 일찍 시작된다.** 캘린더 라이브러리로 자동 판정하고, 배너에 "오늘은 조기 마감"을 띄운다.

## 3. 🔴 CLOSED 레짐 — 왜 신호를 끊는가

미국 장이 닫혀 있는 동안에도 SOXLUSDT perp은 계속 거래된다. 이때 가격을 만드는 건 오직 크립토 거래자들의 수급이다. 결과:

- 호가창이 얇아 **작은 주문이 큰 캔들을 만든다** → 지지·저항, 돌파, 거래량 신호가 전부 오염됨
- 스프레드가 벌어져 진입·청산 슬리피지가 커짐 → 10배에서는 손절 폭의 상당 부분을 먹음
- 본주 가격이라는 기준점이 없어 **괴리(basis)가 누적**되고, 다음 개장 때 갭으로 한 번에 수렴
- 금요일 20:00 ET ~ 월요일 04:00 ET는 **전 세계에서 이 perp만이 가격을 만드는 56시간**이다. 주말 중 큰 뉴스가 나오면 월요일 개장 갭이 청산 사유가 된다

**규칙:**

| 상황 | 앱의 동작 |
|---|---|
| 🔴 구간, 포지션 없음 | 신호 발행 **중단**. "언더라잉 정지 — 분석 신뢰 불가" 표시 |
| 🔴 구간, 포지션 보유 중 | 청산가 거리·괴리·펀딩만 계속 표시. **청산 경고는 24시간 작동** |
| 금요일 마감 임박 (20:00 ET −60분) | "주말 갭 위험 — 포지션 축소 검토" 배너 |
| 🔴 → 🟡 전환 (04:00 ET) | 누적 괴리 표시. "개장 갭 수렴 진행 중" |

## 4. 시간대별 상세 규칙

레짐 안에서도 기술적 분석이 무력해지는 창(window)들. 각 항목은 `BLOCK`(신호 금지) / `PENALTY -n`(신뢰도 감점) / `WARN`(배너만) / `BOOST`(특정 셋업 가산) 중 하나를 갖는다.

| ET | KST(써머) | KST(표준) | 이름 | 무슨 일이 일어나는가 | 조치 |
|---|---|---|---|---|---|
| 08:30 ±10분 | 21:30 | 22:30 | **경제지표 발표** CPI·PPI·NFP·소매판매·신규실업수당 | 초 단위로 몇 % 튐. 지표는 전부 후행 | `BLOCK` |
| 09:30–09:45 | 22:30 | 23:30 | **개장 15분** | ATR 폭발, 밤새 주문 소화. VWAP·EMA 모두 무의미 | `BLOCK` |
| 09:45–10:30 | 22:45 | 23:45 | 개장 드라이브 | 그날의 방향이 잡히는 구간. 추세 셋업 유리 | `BOOST` 추세 |
| 10:00 ±5분 | 23:00 | 00:00 | **2차 지표** ISM·소비자신뢰·JOLTS | 개장 방향을 뒤집는 경우 많음 | `BLOCK` |
| 11:30–13:30 | 00:30–02:30 | 01:30–03:30 | **런치 구간** | 거래량 급감. 돌파가 대부분 실패 | 돌파 `PENALTY -25`, 평균회귀 `BOOST` |
| 13:30–15:00 | 02:30–04:00 | 03:30–05:00 | 오후 추세 | 오전 추세 재개 또는 반전 | 정상 |
| 14:00 ±30분 | 03:00 | 04:00 | **FOMC 성명** (연 8회) | 이날은 이 시간 전까지 거래량도 죽어있음 | `BLOCK` + 당일 09:30~14:00 `PENALTY -20` |
| 14:30–15:15 | 03:30 | 04:30 | **파월 기자회견** | 문장 하나에 방향 두 번 바뀜 | `BLOCK` |
| 15:00–15:45 | 04:00 | 05:00 | 파워아워 | 거래량 재증가, 추세 가속 | `BOOST` 추세 |
| 15:45–16:00 | 04:45 | 05:45 | **종가 리밸런싱 + MOC** | 아래 5절 — SOXL 특유의 왜곡 | `BLOCK` |
| 16:00 | 05:00 | 06:00 | **본주 마감** | 여기서부터 perp 단독. 괴리 시작 | 레짐 전환 `WARN` |
| 16:05–16:30 | 05:05 | 06:05 | **실적 발표** (NVDA 등) | 수 % 갭. 청산 최대 위험 구간 | `BLOCK` + 보유 시 강한 경고 |

## 5. SOXL 고유 이벤트 — 3배 ETF의 구조적 왜곡

### 5.1 종가 리밸런싱 (매일 15:45–16:00 ET)

레버리지 ETF는 다음 날에도 3배 노출을 유지하기 위해 **매일 장 마감 직전에 포지션을 조정**한다. 방향은 항상 그날 움직임과 같은 쪽이다.

```
그날 SOXX 상승 → SOXL은 마감 직전 추가 매수 → 상승 가속
그날 SOXX 하락 → SOXL은 마감 직전 추가 매도 → 하락 가속
```

즉 **마감 15분 전 움직임은 수급이지 신호가 아니다.** 이 구간의 돌파를 따라가면 16:00 직후 되돌림에 맞는다. `BLOCK` 처리하되, 배너에는 "종가 리밸런싱 구간 — 방향 가속 중, 신규 진입 금지"로 이유를 명시한다.

### 5.2 SOXX 상위 종목 실적

SOXL 변동의 대부분은 몇 개 종목이 만든다. 아래 종목의 실적 발표일은 **당일 전체를 고위험으로 표시**한다.

`NVDA` · `AVGO` · `AMD` · `TSM` · `INTC` · `QCOM` · `TXN` · `MU` · `LRCX` · `AMAT`

특히 **NVDA 실적일**은 SOXL이 하루에 10~20% 움직일 수 있다. 10배 포지션은 이날 밤 청산 확률이 매우 높다. 앱은 D-3부터 카운트다운을 띄운다.

### 5.3 월간·분기 이벤트

| 이벤트 | 시점 | 조치 |
|---|---|---|
| 옵션 만기 (OPEX) | 매월 셋째 금요일 | `WARN` — 특정 가격대에 고정되려는 힘 |
| 쿼드러플 위칭 | 3·6·9·12월 셋째 금요일 | `PENALTY -20` 종일 |
| 월말 리밸런싱 | 매월 마지막 2거래일 15:00 이후 | `WARN` |

### 5.4 변동성 필터 (VIX / SOXX 실현변동성)

VIX가 25 이상이거나 SOXX 20일 실현변동성이 상위 20%면, **10배 레버리지에서 정상 손절폭이 노이즈에 걸린다.** 이때는 신호를 내되 "권장 레버리지 5배 이하" 경고를 붙인다.

## 6. 데이터 소스

| 데이터 | 소스 | 갱신 | 상태 |
|---|---|---|---|
| 미국 거래일·반휴장·개장시각 | `pandas_market_calendars` (NYSE 캘린더) | 로컬 계산 | ✅ Phase 1 |
| FOMC 일정 | 연준 공식 일정 (`data/events.yaml`) | 연 1회 | ✅ Phase 1 |
| 경제지표 일정 | **FRED** `/fred/releases/dates` (무료 키) | 하루 1회 + 장 시작 전 | ⏳ Phase 1.5 |
| 실적 일정 | yfinance (키 불필요) · 폴백 Finnhub | 하루 1회 | ⏳ Phase 1.5 |
| VIX | yfinance `^VIX` / Alpaca | 1분 | ✅ Phase 0 |
| SOXX 실제 가격 (괴리 계산용) | Alpaca (본장), yfinance | 1분 | ✅ Phase 0 |

### 이벤트 소스 설계 원칙 (Phase 1.5)

1. **손으로 적은 것이 항상 이긴다.** `data/events.yaml` 은 자동 수집이 붙은 뒤에도
   남으며, 자동 항목을 덮어쓰는 오버라이드 레이어로 동작한다. 자동화는 편의이지
   의존 대상이 아니다 — 무료 소스는 예고 없이 바뀐다.
2. **수집 결과는 DB에 스냅샷으로 남긴다.** 소스가 죽거나 오프라인이어도 게이트는
   마지막 스냅샷으로 계속 돈다.
3. **낡은 일정으로 조용히 도는 것이 가장 위험하다.** 마지막 동기화가 24시간을 넘으면
   `SessionContext.warnings` 에 "이벤트 정보 오래됨"을 넣어 화면에 띄운다.

### FRED 발표 시각 매핑

FRED 릴리스 캘린더는 **날짜만 주고 시각을 주지 않는다.** 미국 지표 발표 시각은
사실상 고정이므로 아래 매핑으로 채운다.

| 발표 기관·지표 | 시각 (ET) |
|---|---|
| BLS·BEA·Census — CPI, PPI, 고용상황(NFP), 신규실업수당, 소매판매, GDP, PCE | 08:30 |
| ISM 제조업/서비스, 컨퍼런스보드 소비자신뢰, JOLTS | 10:00 |

중요도(high/medium/low)도 FRED가 주지 않으므로 관심 릴리스 화이트리스트로 관리한다.

## 7. 구현 형태

이벤트 규칙은 코드에 흩뿌리지 말고 **하나의 선언적 테이블**로 둔다. 새 규칙 추가가 데이터 한 줄이 되도록.

```yaml
# src/th/sessions/rules.yaml
- id: opening_15m
  session: RTH
  window: { start: "09:30", end: "09:45", tz: America/New_York }
  action: BLOCK
  reason_ko: "개장 직후 15분은 변동성이 폭발해 지표가 왜곡됩니다"

- id: lunch_lull
  session: RTH
  window: { start: "11:30", end: "13:30", tz: America/New_York }
  action: PENALTY
  applies_to: [breakout]
  points: -25
  reason_ko: "런치 구간은 거래량이 줄어 돌파 실패율이 높습니다"

- id: etf_rebalance
  session: RTH
  window: { start: "15:45", end: "16:00", tz: America/New_York }
  action: BLOCK
  symbols: [SOXLUSDT, SOXSUSDT]
  reason_ko: "3배 ETF 종가 리밸런싱 수급이 방향을 가속시키는 구간입니다"

- id: econ_release
  source: economic_calendar        # 동적 — 캘린더 API에서 주입
  importance: high
  window_offset: { before_min: 10, after_min: 10 }
  action: BLOCK
  reason_ko: "{event_name} 발표 전후 10분"
```

### 엔진 인터페이스

```python
ctx = sessions.get_context(symbol="SOXLUSDT", at=now_utc)
# → SessionContext(
#     regime="RTH",
#     regime_ends_in_sec=8040,
#     blocked=False,
#     penalties=[Penalty(setup="breakout", points=-25, reason_ko="런치 구간…")],
#     boosts=[...],
#     next_event=Event(name="FOMC 성명", in_sec=5400, importance="high"),
#     warnings=["NVDA 실적 D-1"],
#   )
```

전략 엔진은 `ctx.blocked`가 True면 **셋업 평가를 아예 시작하지 않는다.** 이 순서를 지키는 것이 중요하다 — 계산해놓고 나중에 가리면, 언젠가 UI 어딘가로 새어 나간다.

## 8. 테스트로 고정할 것

- 서머타임 전환일(3/8, 11/1) 전후로 레짐 경계가 정확히 1시간 이동하는가
- 반휴장일에 13:00 ET 이후가 `CLOSED`로 잡히는가
- 미국 공휴일 전체가 `CLOSED`인가
- `BLOCK` 구간에서 `/analyze`가 절대 `direction != none`을 반환하지 않는가 ← **가장 중요한 테스트**
